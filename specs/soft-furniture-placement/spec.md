# 布団・ソファの上に置く布物

2026-10-12のユーザー依頼「ブランケットを布団の上、クッションを布団の上やsofaの上に置けるようにする」に基づく。Google Docs URLは未設定で未確認。Docs未反映。

## 期待する振る舞いと判断

- 所有家具パレットからブランケット・クッションを追加できる。3D上でベッド、布団カバー、ソファの水平面へドラッグして載せる。
- クッション・ブランケットは `attach_to` に支持先のSceneObject IDを記録する。位置・回転・サイズと支持関係を保存し、API結果の再読込と再提案へ引き継ぐ。
- 支持先はbed/sofa/bed_cover。部屋内に収まること、支持先IDの存在、自己参照がないことをサーバーで確認する。布物の手動サイズ変更は所有物としての編集で、商品色や公開寸法を偽装しない。
- 自動提案は寝具と独立した `blanket` slotを持つ。ベッドカバーが先に配置されていればその上面を利用する。クッションは枕元、ブランケットは足元に折り畳んで配置する。ベッドがない場合はソファの座面を使う。幅・奥行きが載せる面に収まらないものは採用しない。
- ブランケットは公開寸法を商品metadataに残し、折り畳みの描画寸法と区別する。例: 130×170cmの商品を65×42.5cmの折り畳み形状として配置し、説明に折り畳みであることを明記する。
- 手動追加のブランケットは薄い形状、クッションは既存の形状で描画する。既存の80cm小物制限は布物の幅・奥行きには適用せず、支持面の実際の範囲で判断する。
- APIの手動補完カテゴリにblanket/cushionを追加。所有商品の `furniture_detail_id` もこれらのカテゴリを受け入れ、サーバーで商品/モデル情報を復元する。
- `FurnitureEdit.attach_to` を追加し、SceneObject.slotへblanketを追加。Swaggerはrswagから再生成しWeb型も生成する。iOSには新規の操作UIは実装していない。

## 確認

既存アプリが別worktreeを参照しているため、現在のworkspaceを一時コンテナへマウントして検証する。DBへの商品取り込みと実配置確認はトランザクション内で実施・ロールバックする。

- 全100商品のカタログから6畳/予算30,000円でMock生成し、寝具・ブランケット・クッションと水色ラグ、卓上照明、収納ワゴンの採用を確認。合計29,292円。
- ブランケット/クッションの支持先が布団カバーIDで、布団の上面に配置されることを確認。
- 90度回転したソファ上のクッション配置、手動所有ブランケットの支持先保存、存在しない支持先の拒否を確認。
- Webの既存関数を一時実行し、bed/bed_cover/sofaのAPI復元後に配置高さが保持されることを確認。
- 支持家具の移動・回転には布物が追従し、bed→bed_cover→cushionの連鎖も維持する。捕捉済みの表示モデルの支持面変換を含む追従をWebの既存関数で確認。モデル/寸法が変わって載らなくなった場合は支持関係を解除する。
- 新規テストファイルは追加しない。既存RSpec、RuboCop、Swagger/型生成、Web lint/buildで確認する。
- RSpec全47件成功（GEMINI_PROVIDER=developer）。手元のVertex設定では既存のAPIキー有無テストが1件失敗したため、テストの前提に合わせたproviderで確認した。変更対象13ファイルのRuboCop、Swagger生成、Web型生成/lint/buildが成功。

## 未検証・制限

実ブラウザでのマウス/タッチ操作、実Gemini生成、公開環境へのデプロイは未検証。ソファの自動配置高さは全高の半分という既存の近似を使い、手動配置は表示モデルの実水平面を使う。布物のしわ・垂れ下がりは布シミュレーションではなく既存モデル/薄い形状によるプレビュー。

## PR統合時の更新（2026-10-12）

最新mainへ統合し、既存のキャラクター配色・候補分散・複数商品配置・予算を使わないAPIを維持した。上記の予算付き確認は統合前の旧ブランチでの履歴であり、PRの最新APIは予算を受け取らない。水色候補の絞り込みでも対応キャラクターのグッズとユーザー選択商品を保持する。

商品カタログの既存92件は変更せず、今回の8件だけ追加した。現在のimporterは既存DBの管理者編集を保持するため、既存データがあるとseedをスキップする。既存環境では管理画面で追加商品の登録が必要で、デプロイだけで8件が追加されたとは扱わない。JSONの確認日時・公開情報の備考は出典記録として残るが、最新mainのDBではmetadata/checked_at列が廃止されており、そのままAPIに公開される項目ではない。

PR専用worktreeでの最終確認: 専用DB（suggestion_colors_pr_test）を使った既存RSpec全75件成功、backend全138ファイルRuboCop成功、Swagger/型生成とWeb lint/build成功。最新mainの予算なしAPIで100商品の取り込みと水色提案をトランザクション内で確認し、布団カバー上のブランケット/クッションの支持先と高さが一致した（合計38,483円）。最初の共有テストDBでは別worktreeによるスキーマ更新と競合したため、専用DBへ切り替えた。
