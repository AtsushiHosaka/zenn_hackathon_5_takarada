# AI で家具の 3D モデルを作る

管理画面の商品から、商品画像と寸法に似た形の 3D モデルを AI に作らせ、画像を見て採用できるようにする。

## 根拠

2026-10-11〜12 のユーザー依頼（チャット）を根拠とする。Google Docs は未確認・未反映。

- 「3D モデルを作り直す基盤を作れないか。画像やサイズのデータを取り込んで AI に作らせたい」「GCP 上で完結させたい」
- 手元の試験（商品 5 件）と Cloud Run（東京・GPU なし）の試験の結果を受けて、次の 4 点を決めた。
  1. AI で作ったモデルは DB を正にする（台帳 `db/furnitures.json` に載せない）。
  2. AI が書いたコードを動かすジョブは、権限を絞った専用のものにする。
  3. 流れは「1 回作る → 管理画面で画像を見て、採用か作り直しかを選ぶ」。AI に見比べさせる自動の修正はしない（試験で、直して悪くなる例があった）。
  4. 三角形の数の上限、光る素材、そのほかの検査を入れる。

## 流れ

```
管理画面  POST .../furniture_details/:id/model_generations
  API     依頼 (request.json) を builds バケットの generations/<id>/ に置き、ジョブを起動する (待たない)
  ジョブ  商品画像を取得 → Gemini に定義を書かせる → 検査 → 組み立て → 検査 → 確認用の画像を描く → result.json を置く
管理画面  5 秒おきに取得し直す。API は取得のたびに result.json を取り込む
管理画面  画像 (正面斜め・横) と検査の結果を見て、採用か不採用かを選ぶ。「3Dで回して見る」で GLB も確かめられる
  API     採用: GLB を公開バケットへ複製し、家具と 3D モデルを作って、その商品に割り当てる
```

- 本番の API には裏で動く処理（ワーカー）が無い（ActiveJob は inline）。数分かかる処理を API の中で待てないので、AI の呼び出しもジョブの中で行う。
- 生成は 1 回 2〜5 分。同じ商品を同時に 2 つは作れない。20 分たっても結果が無ければ失敗にする。

## ジョブ（`tools/furniture_models/generator`）

- Blender 本体は使わず、Python 用の部品（`bpy` 5.1.2）だけで動く。GPU は使わない。確認用の画像は Cycles の CPU 描画。
- AI には、既存の部品ライブラリ（`lib.py`）・色（`palette.py`）・お手本 3 ファイルと、商品名・種類・寸法・色・素材・商品画像を渡し、既存の書き方（`@asset` を付けた関数 1 つ）で書かせる。Blender の命令を直接は書かせない。
- モデルは `gemini-3.1-pro-preview`（`MODEL_GENERATION_MODEL`）。アプリ本体の軽いモデルでは 3 回とも検査に落ちた。
- 検査に落ちたら、理由を AI に返して書き直させる。AI の呼び出しは合計 3 回まで。
- ジョブは DB にも秘密の値にも触れない。持つ権限は builds バケットの読み書きと Vertex AI の呼び出しだけ。

## 検査（`generator/checks.py`）

| 検査 | 落とすもの |
| --- | --- |
| ソース（実行前） | `math`・`palette`・`lib` 以外の import、`open`・`exec`・`eval`・`getattr` など、`__` で始まる名前と属性、`class`・`try`・`with`、20KB を超えるコード |
| 定義 | `@asset` がちょうど 1 つでない、ファイル名や寸法が依頼と違う |
| 部品のつながり | 外接箱がどの部品とも触れていない部品（浮いた部品・離れた部品）。部品は 120 個まで |
| 部位の名前 | 決まった一覧（`tint`・`wood`・`metal`・`glass` など）にない名前 |
| 色を変える部位 | `tint`・`wood`・`fabric`・`rattan`・`weave`・`leaf`・`pot`・`metal` のどれも無い |
| 光る素材 | `light` 以外が光っている、`light` の強さが 2.5 を超える |
| 透ける素材 | `glass`・`acrylic` 以外が透けている |
| 寸法 | 組み立てた大きさが依頼の寸法から 8% 以上ずれる（既存の `finish` の検査） |
| 重さ | 三角形が 8,000 を超える、GLB が 350KB を超える（既存 301 モデルの 9 割は 6,420・225KB 以下） |

検査を通ったコードだけを、認証に使う環境変数を外した別プロセスで実行する。

## データ

- `furniture_model_generations`：生成 1 回分。商品・依頼した管理者・モデル ID（`ai_<商品ID>_<乱数>`）・状態（`running` / `succeeded` / `failed` / `adopted` / `rejected`）・依頼・結果（検査の一覧、三角形数など、AI の呼び出し回数と時間）。
- 採用すると `furnitures`・`furniture_3d_models` に 1 行ずつ作る。形の種類（`shape`）と推定した辺（`estimated_axes`）は、今までのモデルから引き継ぐ。商品の部位ごとの色は、新しいモデルの主な部位を代表色で塗る形に置き換える。
- AI で作ったモデルは DB だけが持つ。`furniture:import` は台帳に載っているモデルだけを更新し、載っていないモデルを消さないので、リリースで消えることはない。台帳のモデル（手で作ったもの）は今までどおり台帳が正。
- GLB は、採用するまで非公開の builds バケットにある。採用したものだけを公開バケットの `models/furniture/v1/<モデルID>.glb` に置く。builds バケットは 30 日で消す。

## API

管理者だけが使える（`/api/v1/admin`）。

- `POST /furniture_details/:id/model_generations`：生成を始める。
- `GET /furniture_details/:id/model_generations`：その商品の生成を新しい順に。
- `GET /model_generations/:id`
- `POST /model_generations/:id/adopt`・`/reject`
- `GET /model_generations/:id/files/:name`：`front.png`・`side.png`・`model.glb`。画像は認証つきで API が中継する（署名付き URL は使わない）。

## GCP（`infra/gcp/model_builder.tf`）

- サービスアカウント `<project>-model-builder`、バケット `<project_id>-model-builds`（非公開）、Cloud Run ジョブ `<project>-model-builder`（CPU 2・メモリ 4GB・15 分・やり直しなし）。
- API のサービスアカウントに、builds バケットの読み書き、公開バケットへの追加、ジョブを環境変数の上書き付きで実行する権限を足す。
- イメージは `make infra-release` と自動デプロイがビルドして差し替える。ジョブがまだ無い環境では、自動デプロイはこの手順を飛ばす。
- **使い始めるには `make infra-apply` が要る**（Terraform の状態を持っている環境で実行する）。適用するまで、管理画面で「作る」を押すと「設定されていません」と返る。

## 費用

1 個あたり約 0.17〜0.40 ドル（1 ドル 150 円で約 25〜60 円）。ほぼ AI の利用料。

| 作ったもの | AI の呼び出し | 入力 | 出力（考える分を含む） | AI の費用 |
| --- | --- | --- | --- | --- |
| キャビネット | 1 回 | 2.4 万トークン | 1.1 万トークン | 約 0.18 ドル |
| デスク（画像なし） | 1 回 | 2.4 万トークン | 1.0 万トークン | 約 0.17 ドル |
| 透明な椅子（1 回書き直し） | 2 回 | 5.1 万トークン | 2.4 万トークン | 約 0.39 ドル |

- 単価は Gemini 3.1 Pro の入力 100 万トークン 2 ドル・出力 100 万トークン 12 ドル（考える分も出力として課金）で計算した。2026-10-12 に料金の比較サイト複数で確認した値で、Google の公式ページでは未確認。
- 検査に 2 回落ちて 3 回呼ぶと約 0.6 ドル。
- Cloud Run は CPU 2・メモリ 4GB を 2〜5 分。1 回 0.02 ドル程度の見込み（東京の正確な単価は未確認）。保存は 1 個あたり数百 KB で無視できる。
- 200 ドルで作れる数は約 740 個（3 割が 1 回書き直す前提で 1 個 0.27 ドル）。全部 1 回で通れば約 1,100 個、全部 2 回かかれば約 500 個。書き直しの割合は試した数が少なく、目安。
- 今の商品 92 件を 1 回ずつ作ると約 25 ドル。

## 確認したこと・していないこと

- 手元：ジョブを通しで実行（キャビネット 95 秒・検査 9/9 合格）。検査の悪い例 9 通りと、import まわりの抜け道 15 通り。API からジョブを起動して、生成 → 取り込み → 採用 → 商品・3D モデル一覧・家具検索に反映、まで。管理画面の欄の表示。
- Cloud Run（東京・GPU なし）：Blender の部品での組み立て（GLB が台帳とハッシュ一致）と、Cycles・Workbench・EEVEE の描画。
- していないこと：Terraform の適用と、本番の構成での通しの実行。部屋の画面で AI のモデルを置いたときの見え方。台帳を作り直す道具（`manifest.py`）は GLB が手元に無く実行していない。

## 残っていること

- 形の出来は商品による。椅子・棚・ランプ・ソファは似た形になった。背と袖のある椅子は 1 回目のほうが良く、布・植物のような曲面の多い形は試していない。
- 費用は 1 回あたり入力 2〜5 万・出力 1〜2 万トークン（Gemini 3.1 Pro）。料金表は未確認。
- 採用を取り消す操作は無い。元に戻すには、商品の編集欄で 3D モデルを選び直す。
- AI が書いたコードの検査は、決まった書き方以外を落とす方式。ジョブの権限を絞ることと合わせて守る。
