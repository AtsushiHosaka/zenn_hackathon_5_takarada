# 描画エラー後も再読み込みの操作を表示する

## 目的と根拠

2026年10月7日のdogfoodで、同一タブのAPI仕様ページからブラウザの「戻る」を使うと、部屋画面が白くなる現象を1回確認した。2回目は再現せず、再読み込みで復旧した。ユーザーから、この白画面の修正と独立したPR作成を依頼された。

根拠は `outputs/dogfood/20261007-1804-qa/report.md` のISSUE-001と、`qa/11-console-errors.json`。API仕様の通常のリンクは別タブで開く。同一タブの履歴移動で確認した現象として扱う。

Google Docs URLは `docs/project.md` に未設定。今回の依頼とQA証跡を暫定の根拠とし、Google Docsには未反映。

## 受け入れ条件

- アプリの描画中に例外が起きても、白画面だけを残さず、案内と復旧操作を表示する。
- 「再読み込み」はユーザーの操作で現在のURLを再読み込みする。自動で繰り返し読み込まない。
- 「部屋一覧に戻る」はアプリを新しく読み込み、`/rooms` を開く。
- 技術的なエラーやスタックは画面に表示しない。案内には未保存の変更が失われる可能性を記す。
- 案内にキーボードのフォーカスを移し、通常の描画や画面移動を妨げない。

## 判断と実装範囲

`RoomStudioPage` の `useRepositories` で、Reactの `useContext` がnullのdispatcherを参照した記録がある。Provider欠落の場合に投げる独自エラーとは異なり、コードから原因を確定できない。インストール済みのReactとReact DOMはともに19.3.0で、`npm ls react react-dom` に重複はない。

既存の3Dビューには局所的なError Boundaryがあるが、部屋ページ全体の描画エラーは対象外だった。アプリ最上位にError Boundaryを置き、描画エラー時の復旧操作を確保する。Hookを使わない案内とし、履歴に復旧不能な画面状態が残った場合も、新しい文書の読み込みで復旧する。

開発サーバーの古い依存モジュールやキャッシュに関する仮説はあるが、QA時のモジュール応答を保存しておらず、原因を裏付ける証拠は不足している。Vite設定や依存バージョンは変更しない。例外の根本原因を解消したとは扱わない。

このError Boundaryは描画やライフサイクルの例外を扱う。エントリーモジュールの読み込み失敗、イベント処理や非同期処理の例外まで捕捉するものではない。

## 検証

2026年10月7日、`npm run lint` と `npm run build` は成功した。ビルドには既存のチャンクサイズ警告がある。

同一タブのAPI仕様から「戻る」を1回試し、部屋画面は表示された。元のHook例外は再現せず、根本原因の解消は未確認。

一時的に特定のURLでAppの描画例外を起こし、復旧画面・案内へのフォーカス移動・再読み込み操作・部屋一覧への文書遷移を確認した。例外を起こす一時変更を除去後、同じルームの再読み込みで通常表示に復旧することを確認した。故障注入による確認と元の例外の再現は区別する。新規テストは追加していない。
