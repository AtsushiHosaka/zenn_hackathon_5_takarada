# 鏡の反射

GitHub issue #76を暫定の要求元とする。`docs/project.md`のGoogle Docs URLは未設定のため、Docsは未確認・未変更。

部屋に置いた鏡に、その正面にある家具や部屋を反射して表示する。カメラを動かすと、その視点に対応した反射へ更新する。手動家具の「鏡」から追加し、既存の配置・移動・回転・寸法・色・保存操作を使う。色は枠に適用し、鏡面の画像は生成しない。

Three.jsのReflectorで平面反射を描画する。既存のWebGLRendererと描画ループを使い、別の常駐ループは作らない。反射中は他の鏡面、選択枠、番号、配置グリッドを隠し、鏡同士の再帰描画を避ける。OutlinePassなどの深度・マスク描画中は反射画像を更新せず、反射画像への上書きを避ける。反射処理で例外が起きても可視性とrenderer状態を戻す。鏡面同士の多重反射は対象外。裏面は枠と同じ色の板として表示する。

反射用ターゲットは描画領域の縦横比を保ち、各辺を最大512pxに制限する。リサイズ時に更新し、配置プレビュー・シーン再構築・画面終了時に反射用ターゲットと素材を破棄する。

backendの手動家具カテゴリと既存FurnitureEdit契約にmirrorを追加する。大型家具の購入検索カテゴリは変更しない。既存の完全なGLBシーンでは個別編集を許可しない制限を引き継ぐ。DBマイグレーションや新しいAPIはない。iOSの鏡描画と本番の実端末性能は未確認。

ローカル確認：frontendのlint/build成功。関連する既存request specは13件成功、RuboCop成功。Swagger生成は41件のdry-run成功、型を再生成した。新規テストは追加していない。既存の正常系rswag入力に鏡を加え、契約を確認した。

一時スクリプトで透視・平行投影カメラ、視点に対応する反射カメラ、再帰防止、可視性とrenderer状態の復元、リサイズ上限、ターゲット破棄を確認した。ローカルDBのロールバック付き確認で、鏡のカテゴリ・位置・回転・寸法・色がモデル検証、mock生成、DB再読込、serializerを通して保持された。Geminiや本番APIの確認ではない。

一時スクリプトでfrontendの実API adapterも確認し、鏡のカテゴリ・識別子・中心位置から床基準への座標変換・回転がedited_objectsに保持された。

実ブラウザでの反射、編集、保存と再読込、スクリーンショットは共有ブラウザの順番待ち。
