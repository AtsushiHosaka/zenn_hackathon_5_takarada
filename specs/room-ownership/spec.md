# 認証と部屋の所有者分離

## 目的・根拠

公開前確認で、認証済み利用者が他人のプロフィールを更新・削除でき、部屋・提案・写真発行が匿名で利用できることを確認した。本人からの「包括的に接続・検証・公開」依頼に基づく修正。Google Docs URLは docs/project.md が未設定のため未確認・未反映。

## 動作

- users一覧は本人1件。show/update/destroyも本人に限定し、他人のIDは404を返す。
- 部屋の登録・取得、提案の作成・取得、写真のアップロードURL発行は認証必須。
- 新規部屋はJWTの本人に関連付け、本人の部屋・提案だけ取得できる。
- rooms.user_idはnullable。既存の匿名レコードは保存したまま本人APIから除外する。所有者推定・データの再割当て・既存データ削除は行わない。
- 新規写真は photos/users/<user_id>/<uuid>/<index>.<extension> に発行。登録時、所有者のprefixを検証してからGCSの存在確認を行う。既存ジョブの旧写真参照は維持。
- 開発用PUTも期限・キー・形式・サイズを署名に束縛し、匿名の任意キー書き込みを拒否。本番のPUT受け口は404。
- 部屋一覧・サンプル・新規入力・保存済みルームは認証必須。未ログイン時はログインへ誘導し、ログイン・新規登録後に元の画面へ戻す。2026年10月8日の本人依頼により、サンプル閲覧のゲスト許可を廃止する。
- Webのローカル保存とQuery cacheは接続先・API origin・利用者IDごとに分ける。旧未所有の保存領域は残すが、次のログイン利用者へ自動移行しない。アカウント切替で画面を作り直し、前アカウントの遅い生成結果を保存しない。
- storage:verify は VERIFY_USER_ID の明示を要求する。検証ユーザーを推定しない。

## 検証と公開条件

- Web lint・本番ビルド成功。API生成型も再生成。
- ローカルの契約生成はlockfileと同じrswag-specs 2.17.0のDSL/formatterでdry-run。DBとRails実行を省略しており、実動作成功ではない。既存mainの生成結果がRuby YAML版の文字列引用・空白差分だけで再現することを確認。最終的な完全生成一致はGitHub CIで確認する。
- 既存RSpec＋最小401/404契約、RuboCop、通常RailsでのSwagger一致、Web生成型一致はPR #17/#18のGitHub CI成功。
- 統合後の本番inline処理に合わせ、Geminiの総期限90秒（再試行込み）、接続5秒・読取25秒・書込20秒、nginx待機115秒、ブラウザ120秒へ整合。実AIは未呼出し。
- DB列は既存Schemafile適用経路で追加する。適用・api更新の順序を維持し、ローカルworkerがある環境はworkerも同じイメージへ更新する。
- 本番DB・GCP・DNS・既存利用者データはこの変更準備では未操作。
