# 3Dモデルの制作一覧と生成プロンプト

ソファの1〜3人掛け・L字の左右を含め、部屋に置く家具の形とサイズを揃える。家具の追加案25個、現行APIに基づく20個、商品の形状違い10個、Web参照サンプル用4個を挙げた。全案を作る場合は59個。まずは下記の初回セットから着手する。色違いは同じ形状の素材を変えて対応する。

制作する人向けに、一覧、コピー用プロンプト、書き出し条件をまとめた。寸法は幅×高さ×奥行き、単位はメートル。商品写真が未設定なので、プロンプトの細部は商品名を基にした制作案であり、実商品の再現を保証するものではない。

根拠は2026年10月4日に確認したローカル仕様と実装、および「ソファなどの家具をサイズ・形状違いで置きたい。L字も欲しい」というユーザーの追加依頼。Google Docs URLは未設定のため未確認。生成ツールは未指定なので、日本語でツールに依存しない形にした。

同じ形でサイズだけ増やす候補は、2人掛けソファの幅1.30m／1.70m、L字ソファの幅2.10m・奥行き1.40m／幅2.80m・奥行き1.80m、ローテーブルの幅0.75m／1.10m、デスクの幅0.80m／1.20m、本棚の幅0.60m／1.00m。これらも制作案で、59個の数には含めない。

脚・板の厚みや座面高を保ちたい家具は、幅・奥行きに合わせて構造を調整する。現行ローダーは等比スケールなので、同じGLBでソファの幅だけを変更すると高さ・奥行きも変わる。幅だけ違う家具は寸法を調整した派生GLBを用意するか、表示側の対応が必要。L字の左右は別モデルにし、名前にも左右の基準を含める。

配置用には各GLBへ`category`、`variant`、幅・高さ・奥行き、モデルURLを対応付ける案とする。例は`sofa / l_left / 2.40×0.82×1.55`。現在は`variant`を使ったモデル選択が未実装なので、制作後に対応を加える。

L字家具の空いている角は、現在の幅×奥行きの長方形での配置判定では占有領域に含まれる。空き角へ別の家具を入れる判定まで行うには、L字を複数の矩形などで扱う対応が必要になる。

## 共通プロンプトを各モデルの説明に添える

以下の共通文と、作りたいモデルの個別文を一緒に入力する。初回セットの8モデルを同じ画面で見て、形状の細かさと素材表現を揃える。

```text
Webの3Dインテリア配置アプリ用の、単独のインテリア3Dアセットを作成してください。
見た目はローポリのスタイライズド表現。輪郭は実際の家具として自然な比率にし、角をわずかに丸め、フラットな色と控えめな素材表現で仕上げてください。
上・前・横・後ろから見ても形が成立するようにしてください。陰影はアプリ側で付けるため、強い影や照明をテクスチャに焼き込まないでください。
指定した物体だけを作り、背景、部屋、床面、展示台、人、文字、ロゴ、余分な小物は付けないでください。指定の鉢・家具の脚・ランプの台座は含めてください。
後から別モデルとして置く小物は、一緒に作らないでください。ベッドには別売りカバー、デスクには卓上小物、棚には展示物を付けないでください。
単位はメートル。+Yを上、+Zを正面とし、底面の中心を原点、最下端をY=0にしてください。
色を変更する部分は他の部分と別素材にし、可能なら素材名をtintにしてください。木材、金属、植物の葉などは独立した素材にしてください。
アニメーション・リグ・カメラは不要です。GLB形式で使える構成にしてください。
```

軸・素材名・GLB出力を生成ツールが指定できない場合は、生成後に3D編集ソフトで整える。プロンプトだけで書き出し条件を満たしたとは扱わない。

## 書き出し後に寸法・表示を確認する

形式はローカル仕様で決定済みのGLB。以下の軸・原点・容量・素材名は既存Specの案を基にした制作目安で、担当者間で合意済みとは扱わない。

- 1アセットにつき1ファイル。外部画像を参照せず、素材と必要なテクスチャをGLB内へ含める。
- 単位はメートル、+Yが上、+Zが正面。最下端Y=0、X/Zは底面中心。指定寸法には葉・脚・台座なども含める。
- 1点あたり2万三角形以下、容量1〜2MB以内、テクスチャ最大1024pxを目安にする。細かな小物はさらに軽くする。
- 平面のラグ・布・アートにも正の厚みを付ける。現行ローダーは幅・高さ・奥行きのいずれかが0のモデルを受け付けない。
- 色変更部分は`tint`、固定色の木材・金属・葉・透明面は別素材。生成後に素材の分離と命名を確認する。
- 最初の納品はMeshopt・Draco圧縮なし。現行ローダーにはデコーダー設定がなく、圧縮モデルは対応後に検証する。
- 透明なケース、布、葉の裏面と、発光部分を明るい背景・暗い背景で確認する。鏡面の反射や照明の光源はアプリ側の表示設定も必要。

現行の家具GLBは、指定の幅・高さ・奥行きの箱に収まるよう縦横比を保って縮小・拡大する。軸ごとに寸法を合わせる`stretch`と、素材`tint`だけの色変更は未実装。ベッドカバーとカーテンは配置時にScene寸法が変わるため、生成後の形が配置先に合うか確認する。

部屋の床・壁・窓は既存コードが寸法から作る。現行の配置編集では家具ごとのGLBを使う。家具入りの完成した部屋を1つのGLBにすると個別の移動・回転・色変更が無効になるため、今回の制作は個別アセットで進める案とする。

## 制作結果 (2026-10-04)

生成ツールの代わりに、Blenderのスクリプトで59形状すべてを作成した。手順は[tools/furniture_models](../tools/furniture_models/README.md)を参照。出力は`output/furniture_models/furniture/`の87ファイル。内訳は基本59形状、商品別の色・寸法違い16個、サイズ違い12個（2人掛けソファ・L字ソファ左右・ローテーブル・デスク・本棚に各2サイズ）。

- 商品ID・既存家具IDとモデルの対応は`backend/db/furniture_models.json`からDBへ取り込む。対応表には37商品と既存家具3種を収録した。
- 既存の制作検証ではthree.jsのGLTFLoaderで全ファイルを読み込んだ。DB移行時にも全GLBの頂点を測り、寸法と底面中心の原点が指定どおりであることを確認した。最大8,384三角形、329,852バイト、合計8,114,712バイト、圧縮なし。
- 見た目はユーザー指定の参考画像に合わせ、パステル・マット・フラットなイラスト調にした。
- 全モデルにUV (1UV = 1m の箱投影) を付け、フロントの`applyMaterialOverrides`で素材名ごとに色・テクスチャを後から張り替えられるようにした。柄・織り目はGLBに含めず、この仕組みで付ける。植物は枝葉の広がりを指定寸法に収めるため、横方向に最大約25%伸縮させている。
- 部屋APIでDBの対応表から`model_url`を補う処理と、Webで不足URLを補う処理を実装した。公開GCSでの配信設定と実接続検証はバケットURL待ち。[運用手順](furniture-models.md)を参照。
